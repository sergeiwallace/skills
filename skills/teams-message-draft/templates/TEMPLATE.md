# Teams message drafts - [FILL: project name]

Every Teams message drafted for [FILL: project name], one file. Pending drafts come first, newest
first by draft date. The sender reviews each draft and sends it themselves, as their own message,
so a draft has no greeting or sign-off preamble and is written in their voice. Posting to Teams is
the sender's decision: they send a draft themselves, or approve that one message for an agent to
send.

Before you draft a new message or edit an existing one, read the
[Voice and style guide](#voice-and-style-guide) and every "Notes on the differences" subsection in
this file, in full, including the archived entries. They are the record of how the sender rewrites
AI drafts, and a draft that ignores them repeats edits they have already made once.

When the sender says they sent a message, ask for a screenshot of the message as it appears in
Teams. Then fill that entry's "Message actually sent" and "Notes on the differences" subsections,
flip its tag to `[Sent]`, and add any new lesson to the voice guide with a citation back to the
notes. Once an entry is sent or dropped, it moves under [Archived Messages](#archived-messages). A
script does the moving: `teams_drafts.py archive` files each entry under its tag and rebuilds the
table of contents and the tracking table, and `validate` checks the result.

Writing rules: answer first, no preamble. Plain sentences, one idea per paragraph. No em dashes,
no punchy one-line closers, no padding lists of three, no bold verdict openers and no hedging
words. No private tracking ids in anything others see. Have someone, or a model, that did not
write a passage review it before it is sent.

### House rules

Conventions the sender set directly. No sent message backs them yet, so each is marked
`(house rule)`. When a sent message later shows one in use, append it to the list above with the
citation and replace its text here with `Moved to guideline N`.

1. No greeting and no sign-off preamble: the sender posts the message as their own. (house rule)
2. Short and to the point. One paragraph per line, with no hard line breaks inside a paragraph, so a
   copy from the rendered preview pastes into Teams cleanly. (house rule)
3. Links are inline hyperlinks with readable display text. Never a bare URL and never a link
   wrapped in backticks, which renders as code and hides the link. (house rule)
4. Name a pull request by number and title so the reader can find it without searching.
   (house rule)
5. The draft is plain text directly under its heading, never wrapped in a code fence or a
   blockquote, because the wrapper comes along when the sender copies the message into Teams. A
   code block that is part of the message, such as a command for the reader to run, is not a
   wrapper. (house rule)
6. A reply quotes the message it answers with the Teams Reply feature and @mentions the person
   asked to act. Never type the quote as a `>` line or a styled blockquote. The draft names the
   answered message in Metadata, and the sender makes the quote with Reply. (house rule)
7. Every message an agent sends is read back after the post, to check Teams stored it as
   approved. (house rule)
8. Settle the text before the send. Teams can refuse to edit a long posted message: "Failed to
   edit. Message too large." (house rule)

## Hard constraints

These hold for every message in this file, drafted or transcribed.

1. ASCII only. A curly quote or apostrophe in a screenshot is transcribed as its straight ASCII
   form; nothing else in a sent message is changed.
2. Inside message text, the team's public tracker keys (for example `PROJ-123`) are the only issue
   references. Never a private tracking id. Keep them out of the metadata and notes too, so a
   passage copied from here never carries one.
3. No email addresses anywhere in this file.
4. Links are inline with display text, never in backticks.
